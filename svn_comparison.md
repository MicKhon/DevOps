# Git vs SVN

Ответы на вопросы задания 4.

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это лёгкая ссылка на коммит. Новый указатель создаётся мгновенно, файлы при этом не копируются. Слияния идут по графу истории.

В SVN ветка обычно выглядит как отдельная папка (`branches/...`) — копия `trunk` на сервере. Переключение и merge занимают больше времени и чаще делаются вручную, поэтому ветки заводят реже.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нельзя. SVN хранит историю на одном сервере: коммит — это новая ревизия именно там. Без сети можно править файлы, но нельзя сохранить ревизию и полноценно работать с ветками.

В Git коммит локальный: полная копия репозитория лежит на компьютере. Сеть нужна только для `push`/`pull`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Старые корпоративные и государственные проекты, где вокруг SVN уже построены права, хуки и регламенты.
- Очень большие деревья с бинарными файлами, когда удобнее выкачивать одну папку, а не весь репозиторий.
- Команды, которым важна жёсткая централизация: один сервер и простая модель «писать в trunk».

Для нового учебного или продуктового проекта разумный выбор — Git.
